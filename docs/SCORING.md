# SCORING — 机会评分逻辑

> 一句话：评分衡量**研究优先级**，不衡量预期收益、胜率或赔率。它回答的是
> "今天这些线索里，哪一条最值得占用稀缺的深度研究时间"。

## 1. 为什么不是收益预测

如果按未来收益拟合权重，系统会退化成一个未经严格回测的信号服务，且必然过拟合、引入前视偏差。
用户的目标是"发现值得研究的问题"，因此评分维度全部是可解释的研究价值代理变量。
历史回放用于检验**区分度与稳定性**（见 docs/VALIDATION.md），不用于优化收益。

## 2. 八个维度（权重合计 1.0）

| 维度 | 权重 | 计算 | 为什么 |
|---|---:|---|---|
| `anomaly_strength` 异常强度 | 0.22 | 贡献异常的最大 score（0–1） | 不异常就不值得研究；避免变成"最大涨跌幅榜"，但异常是必要条件 |
| `economic_impact` 经济影响 | 0.18 | `0.6×全球重要性 + 0.4×传导广度`（广度=受机制影响的资产数/5，并乘以机制置信度，截断） | 大市场、强传导的现象对组合影响更大 |
| `expectation_gap` 预期差 | 0.20 | 实测代理的可靠性加权均值（仓位 / 估值 / 驱动残差）；无可用代理时为 `None`，得分 0 且不得升为重点研究 | 价格与基本面/预期偏离处才可能有错误定价；"未知"不能当作"有机会" |
| `repricing_potential` 重定价空间 | 0.12 | `|价格距200日均线|/15%`，截断到 [0,1]（回撤已在异常强度中，不重复计入） | 均值回归/重估的空间；权重较低，因为大幅偏离可能持续 |
| `catalyst` 催化 | 0.10 | 事件距离：≤10天=1.0，≤30天=0.6，≤90天=0.2，否则 0.1 | 没有触发的研究问题容易变成永久"观察"；但催化难以事前观测 |
| `timing_window` 时间窗口 | 0.06 | 原型默认周期与实际 horizon 一致=1.0，否则 0.5 | 1 日冲击不该占用 12 个月的研究预算 |
| `risk_liquidity` 风险与流动性 | 0.06 | 流动性等级 0–4 映射到 [0.1,1.0] | 难以研究的标的优先级降低 |
| `evidence_quality` 证据质量 | 0.06 | `0.45×来源层级 + 0.25×独立证据 + 0.15×机制置信度 + 0.15×反证据惩罚` | 官方源、多源交叉、机制支持更值得投入 |

权重理由逐项写在 `config/scoring.yaml` 的 `rationale` 中；修改权重必须同步更新本文件与 `DECISIONS.md`。

## 3. 预期差如何度量（P1-01 修复后的定义）

`expectation_gap` 不再是常数，也不再用机制置信度冒充。它由三个**可观测代理**组成，
每个都有明确的数据要求、失效模式和 `None`（不可测量）状态：

| 代理 | 权重 | 度量 | 数据要求 | 不可用时 |
|---|---:|---|---|---|
| `positioning` | 0.35 | CFTC 净头寸/未平仓量在 5 年分布中的单边程度：`2·|pct−0.5|` | 该资产有映射的 COT 市场且报告在 21 天内 | `None` + 原因 |
| `valuation` | 0.25 | 估值分位距中性：`2·|pct−0.5|` | 仅美国宽基/成长，CAPE 在 120 天内（陈旧即不可用） | `None` + 原因 |
| `residual_divergence` | 0.40 | 资产近 1 个月收益中**无法由**市场/美元/利率（贵金属另加 TIPS 代理）解释的残差 z | ≥36 个月度观测、回归 R²≥0.10、|z|≥1.5、残差与价格同向 | `None` + 原因 |

合成：`value = Σ(可用权重×值)/Σ(可用权重) × (可用权重/适用权重)`。
覆盖度低会**降低**得分；三者都不可用时 `value=None`，该候选最多 `watch`。
`deep_research` 额外要求：`value≥0.15`、`confidence≥0.5`、数据质量≥0.5、无关键数据缺口；
机制型候选还要求 `confidence≥0.40` 且至少 2 项通过 FDR 校正的检验。

**这仍然只是代理，不是"市场预期"本身。** 系统不声称知道一致预期；它度量的是
"仓位单边程度 / 估值偏离 / 无法由标准驱动解释的价格变动"，并在报告中逐项展示。
真正的预期数据（一致预期、期权隐含分布）未接入，一律标为数据缺口。

## 4. 硬门槛（先于评分）

| 门槛 | 规则 | 结果 |
|---|---|---|
| 证据数量 | `len(evidence_for) < 2` | `excluded`，原因"证据项不足" |
| 数据质量 | `data_quality.score < 0.30` | `excluded`，原因"数据质量不满足最低要求" |
| 逻辑要求 | 必须存在机制或背离论证（由原型规则保证） | 不满足则不生成候选 |

## 5. 状态阈值

| 分数 | 状态 | 含义 |
|---|---|---|
| ≥ 0.68 | `deep_research` | 立即交给 investment-agent 深入研究 |
| ≥ 0.52 | `watch` | 持续观察，每次扫描重评 |
| ≥ 0.38 | `low_priority` | 保留记录，暂不投入研究 |
| < 0.38 | `excluded` | 有记录但明确不进入队列 |

其他状态：`new`（首次生成）、`expired`（45 天未复现）、`invalidated`（失效条件触发）、
`archived`（人工归档）。

状态来源（`status_source`）区分三类：

- `auto`：由评分自动产生，**可以升级也可以降级**（旧实现把 `deep_research` 排除在更新之外，是 P1-08 缺陷）；
- `manual`：`goe opp status --set ...` 设置的人工决定，自动评分不会覆盖它，只记录 `auto_status_held` 事件；
- `lifecycle`：过期/失效等生命周期状态，不会被扫描复活。

`deep_research` 只是"建议优先研究"，不等于人工已接受；下游研究任务状态单独记录在 `research_tasks`。

## 6. 评分示例（真实运行，2026-11-14 审计后）

`OPP-0002`（ICE US Dollar Index，临近 US Employment Situation；评分 0.593，状态 `watch`）：

| 维度 | 值 | 说明 |
|---|---|---|
| anomaly_strength | 0.87 | near-1y-high + 小幅相对强弱异常 |
| economic_impact | 0.68 | 美元全球重要性高 |
| expectation_gap | 0.175 | 仓位代理（覆盖度 47%） |
| repricing_potential | 0.219 | 距 200 日均线约 3.3% |
| catalyst | 0.60 | 21 天后的已核验事件 |
| timing_window | 1.00 | 事件窗口与 horizon 一致 |
| risk_liquidity | 1.00 | 高流动性 |
| evidence_quality | 0.639 | 聚合价格 + 官方事件 + 反证据惩罚 |
| **总分** | **0.593** | → `watch`（未达到 0.68 门槛） |

说明：`OPP-0001` 的政策利率候选分数更高（0.603），但政策日期是 BIS 月频可用日且已过去 28 天，
按事件窗口规则被降为 `low_priority`，不进入研究队列。分数最高的候选不一定是研究队列第一位。

## 7. 校准与检验

- **历史回放**（`goe replay`）：检查不同年份的评分分布、类型构成与跨时点稳定性。
- **案例验证**（`goe replay --cases`）：检查高分候选是否出现在重要情景窗口。
- **人工审查样本**：对 `deep_research` 候选逐条阅读，检查文本是否真正提供研究价值。
- **不做**：用未来收益反推权重；把回放命中率解释为盈利能力。

## 8. 已知局限（评分层）

- `timing_window` 当前恒为 1.0：horizon 由原型推导，维度尚不具区分度。保留占位是为了未来按标的流动性与机制半衰期分化。
- `risk_liquidity` 仅按流动性等级映射，未考虑波动率与相关性风险。
- 权重未做统计校准；改变权重需重跑回放并记录 DECISIONS。

## 9. 如何调整（供未来维护）

1. 修改 `config/scoring.yaml` 的权重（保持和为 1.0）或阈值。
2. 在 `DECISIONS.md` 记录理由与预期影响。
3. 重跑 `goe replay --cases` 与 `goe replay --start ...`，比较分布变化。
4. 若某个维度长期恒为 0/1（无区分度），考虑替换为更有信息量的代理，而非微调权重。
5. 禁止为了"让今天有 deep_research"而临时调阈值；阈值应按研究容量设定。

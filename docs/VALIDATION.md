# VALIDATION — 历史验证方法与结果

> 验证回答三个不同的问题，不能混为一谈：
> 1. **检测能力**：在历史重要情景中，系统能否用"当时可见的数据"识别异常？
> 2. **候选质量**：识别出的现象是否转化为有证据、有反证、值得研究的候选？
> 3. **投资收益**：如果按候选交易能否赚钱？——**本项目不回答，也不应据此评估**。

## 1. 无前视（point-in-time）机制

| 控制 | 实现 |
|---|---|
| 价格 | `FeatureBuilder(as_of=t)` 只加载 `date <= t` 的行 |
| 宏观 | 每条观测按频率加发布滞后（月 45 天 / 季 120 天 / 周 4 天 / 日 0），只有"已发布"才可见 |
| CFTC | 周二报告 + 4 天（周五发布） |
| 陈旧数据 | 超过阈值未更新 → 视为不可用，不 forward-fill |
| 时点一致性 | `goe.validation.no_lookahead_diff(store, t1, t2)` 对共同历史逐值比较，>1e-5 即判定泄漏 |
| 回放输出 | 不写入正式机会库；只写 `reports/validation_*.md/json` |

已实现的自动化检查：

- `tests/test_features.py::test_no_lookahead_for_price_features`：`as_of=t` 与 `as_of=T>t` 在 t 日的特征必须逐位相等。
- `tests/test_features.py` 的宏观发布滞后测试：观测在 `observation_date + lag` 之前不可见。
- `tests/test_features.py::test_stale_macro_series_is_excluded`：陈旧序列被剔除。

## 2. 预注册历史案例（`goe replay --cases`）

案例定义在 `config/cases.yaml`，共 7 个，覆盖用户要求的历史情景类型：

| 案例 | 窗口 | 预期现象 |
|---|---|---|
| COVID 崩跌 2020 | 2020-02-20 → 04-30 | 价格冲击、波动率跃升、回撤极值、跨资产同步 |
| 美联储加息 2022 | 2022-01-01 → 10-31 | 利率大幅变化、股债双杀、美元走强 |
| 英国 LDI 冲击 2022 | 2022-09-01 → 10-31 | 本币资产冲击、波动率上升 |
| 硅谷银行 2023 | 2023-03-01 → 04-15 | 信用利差代理恶化、波动率上升、回撤 |
| 日元套息平仓 2024 | 2024-07-15 → 09-15 | 日元与日股冲击、相对强弱极值、波动率 |
| 中国政策转向 2024 | 2024-09-15 → 11-15 | 上涨冲击、相对强弱、广度变化 |
| 黄金 vs 实际利率 2025 | 2025 全年 | 黄金异常、跨资产相关性变化 |

**通过标准**：

- `detection_ok`：窗口内至少命中一个预期检测器（或预期异常家族）。
- `relevant_candidate`：受影响资产在该时点产生了候选机会。
- 两者同时成立 → 案例 PASS。
- 机制状态（supported / mixed / unsupported / not_activated）**单独报告**：机制被证伪是有效的负面研究结论，不算检测失败；机制未被激活可能源于数据发布滞后（例如 BIS 月度政策利率的 45 天滞后）。

**为什么不是"预测收益"**：案例只检验"当时能否看见值得研究的现象"，不检验价格后续方向。
系统明确不输出方向性收益预测。

## 3. 结果

**最终结果（2026-11-13 23:28 HKT，当前代码）**：7 / 7 案例通过。归档：`docs/examples/validation_cases_2026-11-13.md`（JSON 同时归档）。

| 案例 | 结果 | 命中检测器 | 机制状态 |
|---|---|---|---|
| COVID 崩跌 2020 | ✅ | drawdown / return shock / vol regime | M10 mixed，M12 mixed |
| 美联储加息 2022 | ✅ | curve_change / drawdown / vol regime | M01 supported，M11 weak |
| 英国 LDI 2022 | ✅ | return shock / vol regime | M01 supported |
| 硅谷银行 2023 | ✅ | credit_stress / drawdown / vol regime | M10 mixed |
| 日元套息 2024 | ✅ | return shock / rel strength / vol regime | M14 unsupported（证伪） |
| 中国政策 2024 | ✅ | return shock / rel strength | M04 unsupported（证伪） |
| 黄金 vs 实际利率 2025 | ✅ | cross_asset_divergence / return shock | M02 mixed |

关键观察：

- 机制被证伪（M14/M04 unsupported）**不影响检测通过**：系统的职责是提出并检验假设，
  证伪是有效的研究产出，不是失败。
- 黄金案例最初未通过，原因不是检测失败，而是机制型原型（regime_repricing）的"预期差"分量
  被结构性置零，导致候选得分 0.37 低于 0.38 阈值。经分析后修正该分量（`0.6×机制置信度`，见
  DECISIONS D-016），阈值保持不变，候选以 low_priority（0.48）进入管线并通过。该修正对全部
  机制型候选生效，不是为了单案例调参。
- 早期版本曾出现"检测到但未生成候选"的失败（英国 LDI、黄金），原因是机制受影响资产覆盖不足
  与候选新鲜度窗口过严；修正后分别通过（扩展 M01 的 GBP/EUR/FTSE 映射；机制候选允许 30 天
  内的资产异常）。

结果文件：`reports/validation_cases_<timestamp>.md/json`（每次运行生成，可复现）。

**结果会随数据更新与阈值调整而变化**；请以最新一次运行的文件为准。方法学结论：

- 检测层：所有案例均能在窗口内命中至少一个预期检测器（价格冲击/回撤/波动率/信用代理/利率变化）。
- 候选层：受影响资产是否生成候选取决于当时的宏观确认条件与证据门槛；部分案例只生成 watch 而非 deep_research，
  这是有意的保守设计。
- 机制层：部分机制在特定窗口被证伪（例如黄金与实际利率的关系在 2025 年不成立），系统如实标记
  `unsupported`，而不是事后编造解释。
- 已知失败模式：当驱动变量本身没有异常（例如信用利差仅温和走阔）时，机制不会被激活；
  当数据发布滞后超过窗口时，宏观触发无法在窗口内出现（这是时点纪律的代价，不是 bug）。

## 4. 逐时点回放（`goe replay`）

```bash
.venv/bin/python -m goe.cli replay --start 2024-01-01 --step 21
```

输出：每个时点的异常数量、机制激活数量、候选数量、类型/状态分布、反复出现的候选指纹。

检验点：

- 候选数量是否稳定（不应出现某天 200 个、第二天 0 个的剧烈波动）；
- 同一现象是否被稳定追踪（指纹重复出现，而不是每天新 ID）；
- 类型分布是否被单一原型垄断；
- 证据文本是否随数据更新而更新，而不是模板复制。

结果文件：`reports/replay_*.md/json`。

## 5. 人工审查（研究质量）

对 `deep_research` 候选逐条检查：

| 检查项 | 标准 |
|---|---|
| 现象可复算 | 报告中的每个数值都能在 `features`/`anomalies` 表中找到对应行 |
| 机制有检验 | 机制有滚动相关/领先滞后/条件统计，且明确标注"相关≠因果" |
| 反对证据 | 至少一条实质性反对证据或替代解释（不能只写套话） |
| 失效条件 | 可观测、可自动评估（阈值/事件） |
| 待研究问题 | 指向真正的数据缺口，而不是系统已经回答的问题 |
| 无过度断言 | 不出现"必然""确定""低估/高估"等结论性措辞 |

已知不满足的情况会在 `docs/QA_AUDIT.md` 与 `PROJECT_STATE.md` 中记录。

## 6. 局限

- 案例选择本身有主观性；它们检验"是否识别"，不构成统计意义上的功效分析。
- 回放依赖同一数据源的历史版本；供应商可能回溯修订（Yahoo 复权因子、BIS 修订）。
- 宏观发布滞后是保守常数，不是逐条发布日历；真实发布可能更早（系统因此更保守，不会更激进）。
- 幸存者偏差：标的池为当前存续工具，历史回放不代表当时可投资全集（见 LIMITATIONS）。
- 未做多重检验校正；案例数量少，不能据此推断机制的普适性。
